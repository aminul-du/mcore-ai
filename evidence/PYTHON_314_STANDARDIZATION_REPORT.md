## 1. ROOT CAUSE ANALYSIS: WHY LOWER PYTHON VERSIONS (3.13 / 3.12) WERE INITIALLY USED
During early host bootstrapping and prior verification sessions, commands and systemd services invoked lower Python versions due to three root causes:

1. **Debian 13 (Trixie) OS Package Default:**
   - Debian 13 Trixie ships with `/usr/bin/python3` symlinked to `python3.13.5`.
   - When any shell, bash script, or system utility executed `python3` without an absolute path, the Linux kernel resolved `/usr/bin/python3` (`Python 3.13.5`).
2. **Early Virtual Environment Initialization:**
   - The original `/srv/shorborno-agent/venv` was created with `python3 -m venv` prior to compiling Python 3.14, permanently locking its interpreter shebang and `site-packages` to `/usr/lib/python3.13`.
3. **Legacy Backup Residue:**
   - In `/srv/mcore/mcore365/mcoresec/apps/terminal-ai/`, an obsolete backup directory `.venv_backup_3.13.5` remained on disk from earlier migration tests, introducing ambiguity.
